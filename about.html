How this site was built

This page is itself one of the artifacts produced by the ai-app-factory: a pipeline that turns a one-sentence request into a small, working site with no human writing code by hand. Here's how that happened, end to end.

  1. One-sentence ask. Someone wrote a single sentence describing what they wanted: "Create a simple hello-world site to test the ai-app-factory build process."
  2. Drafted design doc PR. An agent expanded that sentence into a short design document — what pages exist, what they contain, how they're tested — and opened it as a pull request for review.
  3. Merged doc triggering issue generation. Once the design doc PR was merged, that merge itself triggered the next step: breaking the design into a sequence of concrete milestones and issues.
  4. Human provisioning. A person set up the one-time things an agent can't: repo settings, GitHub Pages, and the secrets (like an OAuth token) the unattended pipeline needs to act on the repo's behalf.
  5. Milestone/issue seeding. The generated milestones and issues were created in the repo, each scoped to one reviewable change, each labeled so the pipeline knows to pick it up.
  6. Unattended implementation PRs. For each labeled issue, an agent read the issue and this repo's conventions, made the change, ran the checks, and opened a pull request — no one in the loop until review.
  7. Pages deploy. Merging to the main branch triggers a GitHub Actions workflow that publishes the repo's static files straight to GitHub Pages, which is what's serving this page to you right now.
